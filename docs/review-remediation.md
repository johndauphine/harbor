## Migration and cleanup decisions

An identity hashes non-secret connection configuration and the private credential reference; neither the reference nor credential values are exposed. Replacing credentials invalidates accepted work even if the endpoint string stays the same. A metadata-only name change does not alter the identity.

Journals without an identity cannot be bound to whichever credentials happen to exist at restart. They remain visible but cannot send payload. Their owned multipart IDs remain available for exact cleanup. If removing a recorded partial fails, its checkpoint's original file attempt remains intact, `Resumable` is false, and `CleanupError` explains the failure. Startup continues; Retry can repeat cleanup later. After successful cleanup, connection deletion can retire the staged source and journal entry.

Credential rotation does not strand multipart ownership: cleanup may use fresh credentials only at the upload's original endpoint/region/addressing scope, and only to abort the exact recorded ID. An identity-mismatched Retry returns an error after cleanup and never starts replacement payload. A changed endpoint must be restored before that cleanup. Restoring the exact original identity permits a subsequent explicit Retry to the original connection. Credentials still need permission to abort the owned upload; failed aborts retain ownership and continue blocking profile deletion.

## Remaining limits

- The identity contract here covers transfer acceptance/retry and single-file deletion. It does not claim every bucket/folder mutation is bound to a browser listing identity.
- Multipart cleanup never redirects to a different endpoint. If the original endpoint is gone or abort permission is unavailable, its exact ownership record remains pending; provider lifecycle rules or restored access may be needed.
- Legacy transfers cannot recover their unknown original credential revision and must be recreated for payload transfer. Retained source data is not automatically rebound.
- A timeout bounds inactivity, not total duration of an actively progressing large transfer. Scheduler waiting time does not consume the network attempt's budget.
- Closing the connection editor does not cancel a submitted save. Concurrent settings writes are last-commit-wins; generation guards preserve the current UI draft and navigation but do not serialize backend writes. Identity checks continue to protect accepted transfers and file deletions.
- An operating-system credential read or an existing wait for the profile lock is not cancellable. New queue requests reject promptly once shutdown is observed; an enqueue already waiting for a writer rechecks shutdown before admitting a worker. Shutdown still waits for active credential operations to unwind before cache cleanup.
- Final independent reviews, realistic integration checks and their follow-up reviews remain mandatory before merging.
