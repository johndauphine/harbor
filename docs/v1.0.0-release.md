# Harbor v1.0.0

Harbor's first stable release focuses on S3-compatible storage browsing and file transfers. It remains a standalone executable that opens a local browser interface.

## Changes since v0.1.1

- Compact light and dark interfaces, S3-console-style upload and deletion reviews, and bucket creation.
- Background uploads and downloads with explicit cancellation, retry and durable recovery. Large transfers reuse verified progress after network failures or application restarts; interrupted transfers require explicit Retry.
- Parallel large-file transfers and automatic concurrency tuning, with a persistent Fixed option and `--no-auto-tuning` session override.
- Fair shared request admission, isolated throttling feedback and corrected learning for slow requests and changing concurrency.
- Reviewed deletion plans for files, exact folder prefixes and non-empty buckets, including version history and unfinished uploads where safe provider operations are available.
- Upgrade instructions included in every archive and explicit source revision metadata for packaged builds from linked worktrees.

## Download and upgrade

Choose the archive matching your operating system and processor. Verify it against `SHA256SUMS`, extract it into a new folder and follow `README.txt`. Read the included `UPGRADE.md` before replacing an older executable. Finish or stop existing transfers and back up settings while Harbor is stopped. A settings backup does not back up operating-system credentials.

**All packages are unsigned. The Mac executable is not notarized.** Checksums detect changed bytes but do not authenticate the publisher independently of the download source. These packages require no active Apple developer account to build. Manual upgrades are supported; automatic updating is not provided.

## Platform evidence and limits

- **Apple Silicon macOS:** local Safari/Chrome workflow evidence, real AWS S3 and MinIO transfer checks, Mac Keychain lifecycle tests, and native package startup validation.
- **Windows 11 ARM64:** previous Edge application testing in the local Windows ARM VM. Repeat the archive check for the exact release; previous testing is not a substitute for a final-package pass.
- **Windows 11 x64:** native hosted backend, race, multi-GiB integrity, mocked Chrome/Edge browser and archive startup checks. Complete real-storage desktop workflows on native x64 hardware remain unverified.
- **Linux x64:** native hosted backend, race, multi-GiB integrity, mocked browser and archive startup checks. Interactive desktop and real Secret Service credential integration remain unverified. A user D-Bus session and unlocked Secret Service login keyring are required for credential saving.

Windows x64 and Linux desktop packages are available with those validation limits explicitly disclosed. Intel macOS and Linux ARM64 are not packaged. No broader minimum operating-system compatibility is claimed. Record final archive checks against the final release revision before publishing; this document describes scope rather than certifying unchecked packages.

## Known behavior and boundaries

- Uploads are limited to 5 GiB per file and 1,000 files per browser batch. Durable staging needs free local disk space. Browser preparation must finish before closing the tab.
- Transfers of at least 64 MiB can resume verified progress where the provider supports the required operations. Small transfers and explicit cancellation restart from the beginning. Automatic tuning does not guarantee a speed increase on every network.
- Recursive deletion previews are limited to 10,000 operations. Retention, permissions and unsupported safe deletion of mutable null versions can leave contents intact with a reported error. Deletion does not resume automatically.
- Providers that ignore conditional deletion cannot eliminate races with external writers. Use storage-side access controls when writers must be excluded.
- Settings are bound to their location and operating-system credential vault. Portable credential export and arbitrary vault recovery are not provided. Downgrades with migrated credentials or recoverable transfers are unsupported.
- SFTP, FTP and SMB are outside v1.0.0. Regulated federal use is outside the assessed scope.

## Validation approach

Release gates require two independent adversarial reviews, relevant regression tests, native hosted CI and checks of the versioned release packages. Internal testing replaces an outside-user beta for this release. Controlled real MinIO tests verify concurrent slow transfers, throttling and interruption recovery; real AWS tests cover integrity, performance and restart recovery. Those measurements are specific to their recorded environments, not universal performance claims.
